why a skill needs testing

A skill file repeats its mistakes in every run

Your agent follows a skill without second-guessing it, so one wrong rule becomes a wrong program every time the skill loads. When we compiled and ran the claims in our own skill drafts, about one in seven needed correcting: 127 corrections across 912 claims. Testing a skill once costs less than catching each bad run.

Three bugs from the audit and the trials. Each compiles, looks idiomatic and passes a quick test. Only running the code caught them.

use-after-free · blind trial

A copy hook that reads freed memory

A =copy guard that compares addresses misses aliasing, so the copy reads a buffer it just freed. The demo and the stress test still pass. Without the skill, the agent’s container failed this memory-safety check. With the skill, it passed.

 uninitialized memory · our own skill

=dup hooks that run on garbage

Copy into freshly allocated raw storage and the compiler injects a =sink that treats uninitialized memory as a live value. Our verified skill had the right pragma for the wrong reason. A compiler-run test now pins the real rule.
silent test skips · blind trial

A green suite that never runs your new tests

Add a test file and the suite stays green, because the new test never runs. Without the skill, the agent’s runner listed the tests by hand. With the skill, the runner finds every test file.

The pattern holds across the catalog. On 12 of 17 skills, the agent without the skill failed a check that the skill-guided agent passed. Other failures include C-library builds that work on only one machine and fuzz harnesses missing required flags.

Pricing details and billing questions

faq

Questions

They’re markdown files. What am I paying for?

The testing behind them. Each code claim has a program the real compiler builds and runs, the skills are tried on hard agent tasks, and the suite runs again on new compiler builds. When a test exposes a wrong statement, including in our own earlier versions, we fix it and ship it in your next update.

How do I justify this to my engineering manager?

Agent-written Nim that crashes on an unusual path costs a review cycle when you are lucky and an incident when you are not. The skills target exactly those paths. We build and test them on low-cost models, so the agent you already pay for gets them right.

Can I use the skills for my job or commercial work?

The public skills are for non-commercial use. The subscription includes a commercial license for your work, one developer per seat.

I already use Context7 or another docs MCP. Do I need this?

Yes, and keep the MCP. Docs tell the agent what exists. The skills tell it what is safe on today’s compiler, what to avoid and how to isolate a failure.

Will my agent actually use the skills?

Add a two-line pointer to AGENTS.md or CLAUDE.md and it will load the matching skill. Copy the pointer.

Which agents are supported?

Anything NYX installs into: Claude Code, Codex, Cursor, OpenCode, GitHub Copilot, Crush, Pi, Cline, Windsurf, Roo Code, Continue and others. Full list.

What happens if I cancel?

Repository access ends at the end of the paid period and updates stop. You keep the versions you received under the license. NYX deletes nothing.

Can I get a refund?

No refunds once repository access has been granted: the files are yours to keep. EU and UK consumers can withdraw for a full refund before access is granted. Statutory rights for faulty or undelivered content always apply. See the refund terms.
