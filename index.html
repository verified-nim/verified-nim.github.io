What changes in your agent’s Nim work

Without guidance, strong models still write Nim that builds, passes its tests and matches the expected output. What they skip is the work a reviewer then has to ask for. The skills put that work into the agent’s own routine.

Bug reports a maintainer can act on

The agent cuts the reproducer to the minimum, runs it to confirm it fails every time and quotes the Nim version and the failing output. Without the skills, not one run on either model stated a reproduction rate.

Ports that put inherited bugs on record

When a port from C keeps a defect on purpose, the defect is on record in the code and in the porting notes. Without the skills, no run recorded it, so the next maintainer finds it the hard way.

Validation once, at the trust boundary

The agent validates untrusted input once, where it enters, and trusts what the build already proved. Without the skills, error-handling code re-checked data the compiler had already checked in every run at three of the four model and effort settings. See the pattern in code.

A sanitizer that reports every memory fault

Debugging scripts stop Nim’s own crash handler from swallowing segmentation faults, so AddressSanitizer prints its report. Without the skills, every DeepSeek V4.1 Flash run let the handler swallow the fault, at both effort levels.

A skill file repeats its mistakes in every run

Your agent follows a skill without second-guessing it, so one wrong rule becomes a wrong program every time the skill loads. When we compiled and ran the claims in our own skill drafts, about one in seven needed correcting: 127 corrections across 912 claims. Testing a skill once costs less than catching each bad run.

Three bugs from the audit and the trials. Each compiles, looks idiomatic and passes a quick test. Only running the code caught them.

A copy hook that reads freed memory

A =copy guard that compares addresses misses aliasing, so the copy reads a buffer it just freed. The demo and the stress test still pass. In a blind trial, the agent’s container failed this memory-safety check without the skill and passed with it.

=dup hooks that run on garbage

Copy into freshly allocated raw storage and the compiler injects a =sink that treats uninitialized memory as a live value. Our own verified skill had the right pragma for the wrong reason. A compiler-run test now pins the real rule.

A green suite that never runs your new tests

Add a test file and the suite stays green, because the new test never runs. In a blind trial, the agent’s runner listed the tests by hand without the skill. With the skill, the runner finds every test file.

The pattern holds across the catalog. On 12 of 17 skills, the agent without the skill failed a check that the skill-guided agent passed. Other failures include C-library builds that work on only one machine and fuzz harnesses missing required flags.

Questions

Don’t strong models already know Nim?

They know how to write correct Nim. In the benchmark, 74 of 75 scored runs with the skills and 77 of 77 without passed every correctness check: the build, the tests and output parity. The skills add the part a correctness check never asks for: the workflow and code quality of a careful Nim engineer. More on this.

They’re markdown files. What am I paying for?

The testing behind them. Each code claim has a program the real compiler builds and runs, the skills are tried on hard agent tasks, and the suite runs again on new compiler builds. When a test exposes a wrong statement, including in our own earlier versions, we fix it and ship it in your next update.

How do I justify this to my engineering manager?

Without guidance, someone trims the reproducers, documents the inherited bugs and deletes the duplicate checks during review. The skills move that work into the agent’s routine, so it arrives done, the same way each run. The benchmark shows the difference on two models, and the compiler audit shows the guidance itself is right.

Do the skills make the agent cost more?

On workflow-heavy tasks a run does more work, so it often costs more. It also finishes far more often, so each passing run costs less. For DeepSeek V4.1 Flash, cost per passing run was 35% lower at maximum effort and 46% lower at low effort with the skills. The numbers.
