What changes in your agent’s Nim work

Strong models write Nim that builds and passes its tests. What they skip lands on your reviewer. The skills make it part of the agent’s routine.

Bug reports a maintainer can act on

The agent cuts the reproducer to the minimum, runs it until it knows how often it fails, and quotes the Nim version and the failing output.

Ports that put inherited bugs on record

When a port from C keeps a defect on purpose, the agent records it in the code and the porting notes. The next maintainer doesn’t find it the hard way.

Validation once, at the trust boundary

Untrusted input is checked where it enters. Data the compiler already proved is left alone. See the pattern in code.

A sanitizer that reports memory faults

Debugging scripts stop Nim’s crash handler from swallowing segmentation faults, so AddressSanitizer prints its report.

In a blind benchmark on DeepSeek V4.1 Flash and GPT-6.1 Sol, runs did all of this 56 of 57 times with the skills and fewer than a third of the time without. See the benchmark.

A skill file repeats its mistakes in every run

Your agent follows a skill without second-guessing it, so one wrong rule becomes a wrong program every time the skill loads. When we compiled and ran the claims in our own skill drafts, about one in seven needed correcting: 127 corrections across 912 claims. Testing a skill once costs less than catching each bad run.

Three bugs the audit caught. Each compiles, looks idiomatic and passes a quick test.

A copy hook that reads freed memory

A =copy guard that compares addresses misses aliasing, so the copy reads a buffer it just freed. The demo and the stress test still pass.

=dup hooks that run on garbage

Copy into freshly allocated raw storage and the compiler injects a =sink that treats uninitialized memory as a live value. Our own verified skill had the right pragma for the wrong reason. A compiler-run test now pins the real rule.

A green suite that never runs your new tests

Without the skill, the agent’s runner listed the tests by hand, so a new test file never runs and the suite stays green.
